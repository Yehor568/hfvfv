# Product Hunter

Сервіс підбору товарів для лендінгів під Meta Ads (Україна, оплата при отриманні). Він рахує реальну прибутковість товарів за даними Meta і LP-CRM, оцінює нових кандидатів (Product Score 0–100) і веде тести за протоколом.

Концепція: [docs/CONCEPT.md](docs/CONCEPT.md). Excel-модель, з якої перенесено формули: [model/Product_Hunter_Model.xlsx](model/Product_Hunter_Model.xlsx).

## Що вміє (ітерація 1)

| Розділ | Що показує |
|---|---|
| **Огляд** | Беззбитковий і цільовий CPL, спенд, ліди, прибуток, ROMI, шортлист «в тест», активні тести |
| **Товари** | Спенд, ліди, CPL, апрув/викуп (з LP-CRM або середні), прибуток, ROMI і статус кожного товару; фільтр по датах |
| **Кандидати** | Score, CPL-фільтр і рішення; перевірка в Meta Ad Library (ЄС); готовий запит для аналізу психології в Claude (варіант Б) |
| **Тести** | Для товарів у статусі «Тест»: йде тест / стоп / масштабувати / нові креативи |
| **Аудиторія** | Спенд, ліди, CPL і CTR за віком і статтю |
| **Налаштування** | Економіка, ваги Score, протокол тесту, імпорт CSV з LP-CRM, відповідність статусів |

## Запуск на сервері (Docker)

```bash
git clone <repo> /opt/product-hunter && cd /opt/product-hunter
cp .env.example .env          # заповніть токени і пароль дашборду
docker compose up -d --build  # дашборд: http://<сервер>:8000
docker compose run --rm web python -m app.cli seed          # стартові дані з пілоту
docker compose run --rm web python -m app.cli sync-meta     # реальні дані Meta за 90 днів
```

Щоденне оновлення: [deploy/crontab.example](deploy/crontab.example). Дашборд відкривайте через HTTPS (наприклад, за nginx/Caddy) і обов'язково задайте `DASHBOARD_PASSWORD`.

## Запуск локально (без Docker)

```bash
pip install -r requirements.txt
python -m app.cli seed
uvicorn app.web.main:app --reload    # http://localhost:8000
python -m pytest                     # тести
```

## Команди

| Команда | Що робить |
|---|---|
| `python -m app.cli seed` | Завантажує стартові дані з `data/seed.json` (пілот 01.10.2026) |
| `python -m app.cli sync-meta --days 90` | Статистика кампаній по днях + вік/стать з усіх кабінетів `META_AD_ACCOUNT_IDS` |
| `python -m app.cli import-crm orders.csv` | Імпорт замовлень з CSV-вивантаження LP-CRM |
| `python -m app.cli lpcrm-probe` | Перевірка API LP-CRM: показує сиру відповідь |
| `python -m app.cli sync-crm --days 90` | Завантаження замовлень через API LP-CRM |

## Доступи (`.env`)

- **`META_ACCESS_TOKEN`**: токен system user з Business Manager з правом `ads_read` на ваші кабінети. Для Ad Library акаунт має пройти підтвердження особи на facebook.com/ID.
- **`LPCRM_API_KEY`**: LP-CRM → Налаштування → Система → API-ключ. Зберігайте тільки в `.env` на сервері.

## Як товари зв'язуються між Meta і LP-CRM

- **Meta**: код товару береться з назви кампанії за шаблоном `id<число>` (`id260_Max_rk1_блендер_…` → `id260`). Кампанії без коду показуються окремо як «спенд без коду товару».
- **LP-CRM**: за ID товару в замовленні (`72` → `id72`). Якщо ID немає, система шукає за назвою: у картці товару заповніть «Назви товару в LP-CRM».
- **Апрув і викуп по товару** беруться з LP-CRM, якщо в нього ≥ 30 замовлень (налаштовується). Інакше використовуються середні значення з налаштувань.

## Відомі обмеження

- **API LP-CRM не перевірений.** Документація була недоступна під час розробки, тож назва методу (`getOrdersByTime`) і поля відповіді — припущення. Спершу запустіть `lpcrm-probe`. Імпорт CSV працює незалежно від цього.
- **Meta Ad Library API** віддає комерційну рекламу тільки для країн ЄС. США перевіряються вручну на сайті Ad Library.
- **Стартові дані** (`seed`) — це агрегат за 90 днів, без розбивки по днях. Після `sync-meta` з'являться дані по днях.
- **Ще немає збирачів** Google Trends, Prom/Rozetka, Amazon/TikTok — це наступна ітерація. Поки оцінки «Тренд» і «Насиченість UA» вносяться вручну.
